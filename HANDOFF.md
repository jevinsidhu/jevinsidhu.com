## Password gate on /clips

`middleware.ts` (root, Vercel Routing Middleware — platform-level, so it works with the static Astro build) gates `/clips`, `/clips/:path*` and `/media/clips/:path*`. `/`, `/og/*` and `clips-thumb.jpg` stay public so link previews still unfurl. The cookie `clips_key` holds the SHA-256 of `CLIPS_PASSWORD` (raw password never stored/echoed); 30-day Max-Age, HttpOnly+Secure+SameSite=Lax. `src/pages/unlock.astro` is the styled gate; its POST is handled by the middleware itself, which redirects back with `?e=1` on a bad password and honours `?next=` (same-origin only, so it can't be used as an open redirect). **Fails open** when `CLIPS_PASSWORD` is unset — a missing env var must never lock the whole site out.

Current password: `put-creators-first`. To change: Vercel dashboard → Project → Settings → Environment Variables → edit `CLIPS_PASSWORD` (all three envs) → then redeploy (env is injected at deploy time, so an existing deployment keeps the old value). CLI equivalent: `vercel env rm CLIPS_PASSWORD production -y` then `printf 'newpw' | vercel env add CLIPS_PASSWORD production`, then push any commit.

Verified live: gated 307→/unlock, wrong password 303→`?e=1`, correct 303+cookie→200 on page and media, forged cookie rejected, home/OG unaffected.
